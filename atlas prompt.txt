Purpose & context

Meeewwaaww is building a personal website called Atlas — a self-hosted daily assistant dashboard deployed via GitHub Pages (public repo: Anthony4102/j) with Supabase (free tier) as the backend. The project started as a simple Budget Tracker and has evolved into a multi-tool personal command center. The stack is entirely static (HTML/CSS/JS, no server), with all logic running client-side. Key constraint: no API keys can be exposed in the public repo, and zero-cost architecture is a hard requirement.

Current state

The project has grown to include several tools and shared infrastructure:

"Ask Atlas" console (/atlas/) — slash-command parser with natural-language aliases (no LLM API); supports commands for expenses, income, balance, tasks, notes, and more
Settings panel — slide-out dashboard panel handling dark mode, name greeting, currency, tool visibility toggles, Supabase connection check, and local cache clearing; stored in a single localStorage key (atlas-settings.js) with Supabase sync
Live widgets panel — News/Weather/YouTube/Social Trends with location toggle (PH/International), city dropdown with Open-Meteo geocoding, item-count control, YouTube category filter, and Supabase cross-device sync via user_settings table
Budget Tracker — partially connected to Supabase with a localStorage fallback pattern (adopted as the standard for all tools); received mobile improvements (floating action button, bottom nav bar)
Shared infrastructure — /css/global.css and /js/supabase.js shared across all tools; each tool lives in its own folder

The conversation ended with a requested full UI polish pass on the Budget Tracker (spacing, shadows, typography) not yet delivered — this is the immediate next task.

Key learnings & principles

Zero-cost, zero-server constraint shapes every architectural decision — no LLM APIs, no backend functions for now
localStorage + Supabase sync pattern is the established standard for all tools (local-first with cloud backup)
Variable naming conflicts are a known pitfall: atlasSupabase was declared in both supabase.js and widgets.js, resolved by renaming the widgets instance to atlasWidgetsClient — new tools should follow this namespacing discipline

Tools & resources

Hosting: GitHub Pages (public repo Anthony4102/j)
Database: Supabase (free tier)
Weather/Geocoding: Open-Meteo API
Stack: Static HTML/CSS/JS (no frameworks or build tools referenced)
